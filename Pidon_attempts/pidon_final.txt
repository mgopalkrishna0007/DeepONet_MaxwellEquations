architecture 

The DCO is implemented using a modified U-net architecture
We extended the U-net framework by incorporating 3-D convolutional kernels to solve 3-D problems. We also added an
extra downsampling branch to function as the trunk network in
the DeepONet, allowing it to process coordinate information.
As a DCO, this trunk network decodes coordinate information into cell sizes, allowing its application across different
computational domains.
The U-net architecture comprises two branches: a downsampling branch and an upsampling branch. Each branch contains
L levels of corresponding blocks. In each block, there are two
3×3 × 3 convolution filters with an activation function.
we use Gaussian error linear units.
 The padding size of these two convolutional layers is 1 on each boundary, and the step size
of convolutional kernels is also 1, ensuring that the output
dimensions remain unchanged after each block. We add an
additional residual connection within each block to maintain
the gradient flow from the input feature map to the second
convolution layer. This residual connection facilitates deeper
layers in the network to learn residual functions with reference
to the layer inputs, In the downsampling branch, there is a max-pooling layer
between two neighboring blocks. The kernel size of the
max-pooling layer is 2×2 × 2, which halves the feature map
dimensions after each downsampling block. In the upsampling
branch, there is a transposed convolutional layer between each
block. The kernel size of this layer is also 2×2 × 2, doubling
the size of the feature map in each dimension after each block.
Consequently, the output dimensions remain the same as the
input dimensions after U-net computation. The outputs of the two
downsampling branches are combined using the Hadamard
product, which performs element-wise multiplication of the
corresponding values from the branch and trunk networks.
This operation maintains the dimensions of the input feature
map, ensuring alignment of the feature map shapes between
the corresponding blocks in the downsampling and upsampling
branches.
Finally, between the downsampling branch and the upsampling branch, there is a skip connection between the
corresponding block. skip
connection directly copies the output from one downsampling
branch to the corresponding block in the upsampling branch.
This direct connection maintains multiple levels of features in
the training process.
